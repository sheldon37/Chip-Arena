# Community maps and selectable weapons

## Install and test

Open **Mods → Open Mods folder**, make a **Community** directory and copy the RelayYard example directory into it. Restart, check the active pack count, select Relay Yard in Room Options and Relay Saber under Melee. Install the same package on a second client before joining. Change a single animation sample on the guest and restart to exercise content mismatch rejection. Disable community content in Mods and restart to return to the built-in catalog.

For manager integration, install each enabled package in its own immediate child directory beneath a profile-specific content root. Launch the player with `--chiparena-mods "<absolute content root>"`. This selects that profile in place of the manual folder. Disabled packages must be removed from that root or have their content filename disabled. No BepInEx bootstrap is required for these packs. The example directory contains a Thunderstore manifest, 256×256 icon, README and game payload. Zip those four files at the archive root. Registering a game community and adding install/launch rules to the manager are separate external steps.

## Pack format

Use the example at `examples/thunderstore/RelayYard/chiparena.pack.json` as a working template. Each package has one self-contained UTF-8 payload named `chiparena.pack.json`, schema 1, an ID and a three-part version. Use lowercase ASCII letters, numbers and hyphens for local IDs, beginning with a letter. Packs with chips use the existing chip-pack ID rules. The runtime orders packages by ID. The multiplayer revision includes all payload text and the exact bytes of each referenced Windows AssetBundle. Player-hosted and solo games load the content at startup.

- **Maps** use the native UnityMaps map definition. Provide bounds, eight FFA spawns, two four-player team tables, blocks and a navigation graph. Native authored segments, ramps and supported hazard definitions use the same validation rules as shipped maps. Hazard IDs must start with the runtime map ID plus a hyphen. The runtime map ID is `mod.<pack>.<map>`. Set rotation to true to include an arena in random selection.
- **Custom geometry** uses independent indexed triangle meshes in map-local Unity coordinates (metres, Y up), using existing material IDs. Use clockwise front faces and split vertices at hard edges. Solid meshes receive a static MeshCollider and use the world collision layer on every peer. Author navigation links separately. Gameplay blocks handle destructible objects. For original textured environments, build a map prefab with your meshes, materials, lights, LODs and static colliders in the project’s pinned Unity version. Select the prefab and run **Assets → Chip Arena → Export selected map prefab for Windows**. Pick the package directory, set the map entry’s sibling field `"prefab":"arena"`, and include `arena-assets.bundle` in the zip. Keep the prefab at world origin. All dependencies must be in this one bundle. Give each separately installed prefab a distinct Unity asset GUID. GameObjects with scripts, rigidbodies, triggers, cameras or unsupported components are rejected. Use the native map definition for gameplay logic and bot routes.
- **Weapons** get their own catalog entry and display name. Declare exactly one category, melee, ranged or magic, and a public baseWeapon from that class. The base supplies the model, combat rules, abilities and hit timing. The selection and its animation identity survive the switch to the combat base and replicate to guests.
- **Unique chips** use the optional weapon field `unique`. For a new family such as `relay`, the chip condition is `"uniqueWeapon":"relay-yard.relay"`. The category tag and unique condition both apply. Several weapons in a pack can share a family. Use the same ID as the base kit to opt into that kit’s existing signature tag (e.g. baseWeapon and unique both glaive). Omit unique for ordinary class chips. External chips use the existing supported stat effects and stack rules.
- **Animations** are sampled local Unity bone rotations (normalized x/y/z/w quaternions), uniformly spaced across the stated duration in seconds. Only named tracks override the base pose. Supported actions are idle, move, attack, cast, block and reload. Idle/move loop. One-shots use replicated action times. Bone names match CapturedRig, e.g. right-shoulder, right-elbow and right-wrist. Animation samples affect presentation only. They carry no damage events or authoritative root motion.

To convert a Unity AnimationClip, key local rotations on the generic CapturedRig paths starting at `motion-root/pelvis`. Select the clip and run **Assets → Chip Arena → Export weapon bone animation**. Add the exported object to the weapon’s animations array and choose its action. Humanoid muscle clips need to be retargeted or baked onto that hierarchy first.
