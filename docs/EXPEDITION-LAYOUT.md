# Expedition layout contract (agreed 2026-10-14)

Agreed by Claude on Astra's proposal (`codex/expedition-director`, DEV_LOG 2026-10-14 "Astra:
Expedition director/layout contract for Claude agreement"), with the amendments marked **Amended**
below. Claude owns the layout: geometry, blockout, manifest data and visuals. Astra owns the
director: loader/validator, encounters, combat, network, persistence and migration. This file
describes the data between the two. It does not mean that a playable Expedition exists.

## Ids (accepted as proposed)

| Role | Area id | Map id (UnityMaps.json) | Look (MapLooks.json) |
| --- | --- | --- | --- |
| Outdoor town (world) | `exp-city` | `expedition-city` | `expedition-city` (new: zombie city at dusk) |
| Ward Zero instance | `exp-ward-zero` | `expedition-ward-zero` | `quarantine` (shared with Siren) |
| Second instance | `exp-foundry` | `expedition-foundry` | new, later |
| Third instance | `exp-transit` | `expedition-transit` | new, later |

- First playable slice: `exp-city` + `exp-ward-zero` only. The manifest's instance list is the
  clear requirement; foundry and transit join later through the same contract without code changes.
- Themes: foundry is a factory interior and transit a metro station. These are working themes,
  not approved art; the ids stay fixed whatever the art becomes.
- Existing PvP/Siren map ids (`brickfall`, `factory`, `cybercity`, `siren`) are never repurposed.
- Anchor ids follow the proposal: `exp-city:door:<instance>`, `<instance>:door:exit`, `<area>:cache:N`
  and `<area>:machine:N`. They are case-sensitive, at most 128 characters and pass the existing
  validator.
- **Amended:** a cache anchor's public `kind` is `chest`, the existing public kind, while its id
  says `cache`. Both sides read the kind, never parse the id.

## Geometry: one source, generated map entries

**Amended** (where the proposal left the geometry source open):

- Each area's collision and render geometry is an ordinary map entry in
  `Assets/Conversion/Resources/UnityMaps.json` (blocks, bounds, materials) with a look in
  `MapLooks.json`. It loads, collides and draws like every arena.
- The entries are generated by deterministic scripts in `docs/arenas/scripts/`, as Ward Zero,
  Factory and Cyber City were. Each has a fixture and a Python test that checks the script's own
  analysis (floor reachability, entry points on walkable floor, slot clearance) and
  byte-identical regeneration.
- `expedition-ward-zero` is generated from the current `siren` blocks plus an Expedition overlay:
  an exterior exit door, caches and a boss room if needed. Siren's map is read, never edited. A
  later Siren change reaches the instance only by regenerating, which changes the layout revision.
- Bounds: the town is about 120 × 120 m (`minX -60 .. maxX 60`, `minZ -60 .. maxZ 60`, ceiling 40,
  killY -8). It has a central sanctuary plaza about 24 m across, one entrance per instance on the
  plaza's streets, and a gated final-boss plaza at the north edge. These are greybox targets that
  will be tuned for an 8-player, roughly one-hour clear.

Conventions:
- Units are metres in that area's own world frame, +Y up. `yaw` is in degrees about +Y; 0 faces
  +Z. Volumes are centre, full size and yaw.
- Every `y` is the collider floor surface under the point. There is no origin fallback, and a
  missing record refuses to load with a diagnostic, as proposed.
- A door anchor always carries `building`. Its `yaw` faces out of the doorway (the way a pilot
  walks to leave), so door leaves and seals are drawn in 3D. Before yaw existed they were a HUD
  hologram.
- Slots: each town door has 8 `returns` outside it and each instance exit has 8 `entries` inside
  it. The sanctuary has 8 `slots`. The world start, respawns and checkpoints all use those slots.
- **Amended (spawns):** an enemy spawn record is the existing `PveEntry` shape from PveContent.json
  (`e`, `id`, `kind`, `from`, `exit`, `yaw`, `level`, `clear`, optional `height`/`surface`), plus
  `allow` (archetype ids). The kinds are limited to the ones that already have spawn code and
  entrance animations:
  - `door` (shopfronts and side doors);
  - `vent` (street grates and manholes);
  - `drop` (roof and ledge drops);
  - `breach` (Hulk wall).

  No new kind is needed. Ward Zero's instance uses `"inherit:siren"`: the existing 53 stage entries
  by `e`, because they are tied to that geometry and the generated instance keeps it. The town
  authors its own.
- **Amended (gates):** the final-boss plaza is closed by a director-owned gate volume
  (`exp-city:gate:final`, `opens: "final"`) whose collision follows `FinalUnlocked`. It is director
  metadata, not a public anchor kind.
- The public anchor kinds stay `door`, `machine`, `chest` and `reward`. Reward anchors are only
  ever issued by the authority. Private rewards never get anchors.
- The layout revision covers the manifest plus each referenced map entry's block hash, and it
  takes part in room compatibility and handoff as proposed.

## State presentation reads from the public view

Visuals animate from authority state only and never decide anything. **Amended**, needed for the
animations:
1. **Door and gate state with its clock.** For each door anchor and each gate: `open`, `sealing`,
   `sealed` or `opening`, plus the authority-clock time that state began. Sealing and opening take
   1.0 s on both sides, so the leaves move in step with the collider toggle.
2. **Area transfer barrier.** The target area, the barrier generation and ready / required
   counts, so the transition screen can show the entry with the party's readiness while the map
   loads.
3. **Sanctuary membership.** A public per-member boolean derived by the authority, for the safe
   tint and SAFE tag. The UI never grants it.
4. **Boss arrival.** For each boss entity: its id, archetype and authority-clock spawn time, so the
   boss intro plays once and in step for everyone. Test encounters keep "TEST" in their names until
   a boss design exists.

## Authoring gate

Astra's validator owns refusal at load time: duplicates, bad area, out of bounds, navigation, and
pilot and Hulk clearance at every slot, spawn and return. Claude's generator runs the same checks
offline and fails the draft test first. Both run in the managed relay before the manifest ships.
